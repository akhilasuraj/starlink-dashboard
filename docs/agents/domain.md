# Domain docs

This is a **single-context** repository. Project terminology belongs in root `CONTEXT.md`; architectural decisions belong in `docs/adr/`.

Before exploring or changing a part of the codebase, read `CONTEXT.md` and the relevant ADRs when they exist. If a file does not yet exist, proceed without it. The domain-modeling workflow can create these files when terminology or decisions have actually been established.

Use the terms defined in `CONTEXT.md` in issue titles, plans, code, and tests. If a needed concept is missing, note the gap rather than inventing a competing name. If a proposal conflicts with an ADR, identify the ADR and explain why the decision should be revisited.
